# TASK: GearDrop iOS 首次进入性能（更新：2026-08-04 05:22 EDT）

## Why（一句话）
让首页先显示可用商品，再在后台补齐完整目录，避免首次进入被 5,789 条全量数据和 120 条价格信号查询拖慢。

## 当前状态：代码与本地验证完成，等待提交和新 iOS 构建

## 已确认事实
- App 首次加载原路径为 `ProductsProvider.reload()` → `fetchAllProducts()`；后者串行读取 `products` 每页 1,000 条、共 5,789 条，并在每页到达后重新规范化全部累计行、触发状态更新。
- 首页默认美国区、折扣降序，但原首个请求没有地区过滤，先下载 1,000 条全字段数据；实测首包约 1,645,690 bytes，5 次中位 0.851 秒。
- 原完整目录串行读取约 11.2 MB；首页首轮还会为前 120 条商品分 3 次读取价格历史，实测约 148 KB、2.308 秒。价格历史不阻塞首屏，但会与图片和全量目录争用启动期资源。
- 新启动预览精确读取美国区折扣前 200 条；生产实测 200/200 条均属于美国区且有图，响应约 335,614 bytes，5 次中位 0.496 秒。

## 已完成且已验证
- 无缓存首次进入：先读取 200 条美国区完整商品记录并立即渲染，再后台读取完整 5,789 条目录。
- 后续冷启动：优先读取最近 24 小时的 200 条预览缓存；缓存失效、损坏或存储异常不会阻塞生产数据读取。
- 完整目录不再每页重复规范化和触发 UI 更新；按 `sku_id` 稳定分页，最终搜索、地区筛选和跨区比价仍使用全量目录。
- 首轮价格信号窗口从 120 缩到 20，滚动时每次增加 40；对应实时历史查询从 3 次缩到 1 次。
- `npm test`：25/25 通过；`npm run typecheck`：exit 0；`npm run verify:live-data`：5,789 条全量、200 条启动预览均通过；独立 iOS export：1,442 modules、3.9 MB HBC、exit 0。
- 完整 `npm run verify` 在 Expo Doctor 停止：项目现有 8 个 Expo/RN 依赖低于 SDK 57 当前推荐补丁版本。这与本次代码无关，未把依赖升级混入性能修复。
